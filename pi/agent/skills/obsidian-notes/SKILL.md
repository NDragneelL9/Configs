# Obsidian Notes

Vault: `D:\Z\ObVault`. Obsidian должен быть запущен (MCP-сервер живёт внутри плагина).

## Дневная заметка: 4 шага

Единственный путь работы с дневной заметкой и задачами. Выполняй шаги по порядку.

### Шаг 1. Обеспечить существование заметки

```bash
bash C:/Users/JohnDoe_it/.pi/agent/skills/obsidian-notes/scripts/daily.sh <YYYY-MM-DD | today | yesterday | tomorrow>
```

«Сегодня» → `today`, «вчера» → `yesterday`, «завтра» → `tomorrow`. Скрипт сам создаёт заметку из шаблона `_Templates/Daily`, если её нет, дожидается рендера и печатает три строки:

```
path=01-Daily/20261130.md
created=false
heading=Monday, November 30th, 2026
```

Готово, когда в выводе есть `path` и `heading` — запомни оба, они нужны дальше. При ошибке скрипт печатает `ERR: ...` (Obsidian не запущен, дата не распознана): сообщи пользователю текст ошибки и остановись.

### Шаг 2. Прочитать заметку

```
vault_read { path: "<path из шага 1>" }
```

Возьми из ответа `version` (число) и убедись, что в тексте есть секция `### Tasks`. Готово, когда есть `version`.

### Шаг 3. Добавить задачу в Tasks

```
vault_patch {
  path: "<path>", targetType: "heading",
  target: ["DAILY NOTE", "<heading из шага 1>", "Tasks"],
  operation: "append",
  within: -1,
  content: "<реальный перевод строки>- [ ] текст задачи",
  ifMatch: <version из шага 2>
}
```

`within: -1` и перевод строки в начале content продолжают последний блок — задача встаёт строкой сразу за последней задачей, без пустой строки между ними. Если в Tasks нет ни одной строки задач (список пуст) — опусти `within` и перевод строки, добавляй как новый блок.

Перевод строки в content — настоящий символ новой строки, а не экранированный `\n`: литеральные два символа `\` + `n` доходят до сервера как есть, и задача приклеивается к хвосту предыдущей строки. Если транспорт не пропускает многострочный content — пользуйся шагом 4 (replace всей секции Tasks со вставленной строкой).

Готово, когда патч вернул новую `version` — запомни её. Затем посмотри на список Tasks из шага 2: если там осталась заглушка `- [ ] Task example`, сразу выполни шаг 4, чтобы убрать её.

Новая задача входит в секцию только через шаг 3 и только в виде `- [ ]` — даже если в итоге должна быть отмеченной. Отмечает её отдельный шаг 4.

### Шаг 4. Изменить или отметить существующие задачи

Шаг 4 работает с задачами, уже напечатанными в секции. Нужна новая задача сразу отмеченной — сначала шаг 3 (добавляет `- [ ]`), затем шаг 4 (меняет на `- [x]`).

Прямо перед правкой прочитай заметку заново:

```
vault_read { path: "<path>" }
```

Возьми из ответа свежую `version` и текущий список Tasks. Правка — замена всей секции: скопируй список из этого чтения дословно (пустые строки между задачами не переноси), измени только нужные строки, верни целиком:

Заглушка шаблона `- [ ] Task example` — мусор: заметив её в секции Tasks при любой работе по лестнице, убери её этим шагом (в списке для replace её просто нет), даже если пользователь о ней не упоминал.

```
vault_patch {
  path: "<path>", targetType: "heading",
  target: ["DAILY NOTE", "<heading из шага 1>", "Tasks"],
  operation: "replace",
  content: "- [x] первая задача
- [ ] вторая задача",
  ifMatch: <version из шага 2>
}
```

### Правила лестницы

- `ifMatch` обязателен в каждом патче; в следующем патче используй свежую `version` из ответа предыдущего.
- HTTP 409 (файл изменился) → повтори чтение, затем патч с новой `version`.
- Патч не нашёл заголовок → повтори шаги 1–2 (заголовок мог измениться).
- Новая задача — только шагом 3 (`- [ ]`); отметить её — отдельным шагом 4 со свежим `vault_read`.
- Лестница правит только секцию Tasks. Прочие правки — reference-разделы ниже.
- Готово = последний патч вернул новую `version`, и в секции Tasks нет заглушки `- [ ] Task example`. Сообщи пользователю путь заметки и что сделано.

## Reference: остальные сценарии

MCP-сервер `obsidian` настроен в Pi (user-level `~/.pi/agent/mcp.json`). Direct-инструменты: `vault_read`, `vault_write`, `vault_append`, `vault_patch`, `vault_list`, `search_simple`. Остальные (`vault_get_document_map`, `vault_delete`, `vault_move`, `vault_copy`, `search_query`, `command_execute`, `open_file`, `periodic_note_get_path`, `tag_list`) — через codemode.

### Обычная заметка

`vault_write { path: "Папка/Имя.md", content: "<markdown>", ifNoneMatch: "*" }` — создать только если не существует. Бинарные расширения (png, pdf, zip, …) `vault_write` отказывает — вложения только через REST `PUT`.

### Произвольные секции

Цель заголовка = полная цепочка от корня (не последний уровень!): `target: ["DAILY NOTE", "Tuesday, November 10th, 2026", "Tasks"]`. Цепочку бери из `vault_get_document_map { path }` или из текста `vault_read`. Операции: `replace`, `prepend`, `append`, `delete`. `append`/`prepend` вставляют новый блок (отделяется пустой строкой); чтобы продолжить существующий список без отрыва — `within: -1` и настоящий перевод строки в начале content (не экранированный `\n` — см. шаг 3). Дописать в конец файла целиком: `vault_append { path, content }`.

### Frontmatter

`vault_patch { path, targetType: "frontmatter", target: "status", operation: "replace", value: "done" }` — значение в `value` (JSON), не в `content`. `append`/`prepend` к пустому или отсутствующему полю падает с 40080 — используй `replace` со списком: `value: ["тег1"]`.

### Поиск, список, удаление

`vault_list { path: "01-Daily" }` — файлы в папке. `search_simple { query, maxResults }` — полнотекстовый поиск. `vault_delete` — в корзину Obsidian (безопасно).

### REST напрямую

`scripts/api.sh METHOD PATH [BODY] [CT]` — обёртка над Local REST API, сама подставляет ключ и CA-сертификат (HTTP-клиент — node fetch). Пустое тело — аргумент `""`; отсутствие аргумента = запрос без тела. `scripts/wait_render.sh <путь-в-vault>` — ждёт завершения асинхронного рендера Templater (0.4–1.3 с), таймаут 10 с → код 1.

Периодические эндпоинты: `/periodic/daily/Y/M/D/` — любая дата (используется daily.sh; POST идемпотентен); `/periodic/weekly/Y/M/D/` — маршрут существует; monthly/quarterly/yearly — 400. POST/PUT/PATCH создают заметку при отсутствии.

## Подводные камни

- Templater рендерит асинхронно: свежесозданную заметку нельзя патчить сразу. Лестница закрыта (daily.sh дожидается); при ручном REST-пути всегда прогоняй `wait_render.sh`.
- `version` из `vault_read`/`vault_patch` — основа `ifMatch`; правки без `ifMatch` затирают чужие изменения молча.
- Успех патча возвращает новую `version` — используй её в следующем `ifMatch`.
- Каталог `.obsidian` недоступен через API (403).
