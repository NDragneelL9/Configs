# Confluence docs (manual download + mdcheck gate)

Confluence за SSO — скачать страницу скриптом нельзя. Пайплайн: сохранение
руками → `to-md` (сам гоняет mdcheck) → зачистка ПДн руками → `mdcheck`
exit 0 → чтение. Секреты ловит автоматика (fail-closed), ПДн — человек по
списку подозрений (fail-visible).

## Железные правила

1. **Никогда не запрашивай Confluence напрямую** (curl, fetch_content, browser).
2. **Сырой экспорт только скармливается `to-md`** — `.doc/.docx/.html/.htm/.pdf`
   агентом не читается: никаким способом (`read`, cat/head/tail, grep,
   node-скрипты), ни целиком, ни фрагментом.
3. **Вывод `to-md` — такой же сырой до mdcheck exit 0.** Конверт из реальной
   доки содержит ПДн; повторный конверт (`--out recheck.md` после правки
   конвертера) сбрасывает гейт заново. Структуру негейтованного вывода
   проверяет `stats` (счётчики, без контента) — других способов нет.
   С файлом работает пользователь: открывает в редакторе и чистит; агент
   показывает ему только замаскированный отчёт mdcheck.
4. mdcheck **exit 1** (секреты) — стоп: пользователь правит файл. «Уговорить»
   находку нельзя; после правки перезапусти mdcheck.
5. mdcheck **exit 3** (подозрения) — покажи пользователю список (значения
   замаскированы, есть номера строк). Читай только после явного «вычистил»
   или «это не ПДн, можно». weak-подозрения (хосты, IP, названия) — на
   усмотрение пользователя.
6. mdcheck **exit 0** — читай. В ответе укажи: «Confluence: `<файл>`, mdcheck:
   чисто» (+ сколько подозрений снял пользователь, если было).
7. Подозрения в отчёте замаскированы; реальные значения не спрашивай, не
   «восстанавливай» и не подставляй. Пользователь сам правит файл.

## Шаги

### Шаг 0. Node

`eval "$(fnm env)"`. SKILL=`C:/Users/JohnDoe_it/.pi/agent/skills/confluence-docs`.

### Шаг 1. Пользователь сохраняет страницу

Попроси: в Confluence меню «…» → **Export → Word** (лучше: чистая структура,
таблицы) или **Ctrl+S → «Webpage, HTML only»**. Файл — куда удобно пользователю
(обычно Downloads). Экспорт Word бывает файлом `.doc` — это MHT-обёртка (MIME +
quoted-printable HTML), `to-md` сам её разворачивает. PDF не подходит: не
редактируется и не конвертируется без потерь — если принесли PDF, попроси Word/HTML.

### Шаг 2. Конвертация + встроенный mdcheck

```bash
node "$SKILL/scripts/confluence.mjs" to-md "<файл.doc|docx|html>"
```

md появится рядом с исходником (`mdPath`). `to-md` сам прогоняет mdcheck
по свежему выводу: отчёт — в том же JSON (ключ `mdcheck`), exit-код to-md =
коду mdcheck (0/1/3; 2 — ошибка) — грязный вывод физически не «дочитается»
цепочкой `&&`. До exit 0 вывод не читается (правило 3).

### Шаг 3. Список для ручной зачистки

Из отчёта (в выводе to-md; после правок файла — отдельным `mdcheck "<md>"`)
покажи пользователю:
- `secrets` — обязательно вычистить (замаскированные образцы, типы);
- `suspects.strong` — ФИО/email/телефоны/док-номера: вычистить;
- `suspects.weak` — пары слов, хосты, IP, строки с логинами: на усмотрение.

Пользователь правит md (find&replace) и говорит «готово».

### Шаг 4. Повторный mdcheck

`exit 0` → читать (правило 6). `exit 1` → снова шаг 3. `exit 3` → правило 5.

## Отладка конвертера

Правишь `confluence.mjs` — проверяй, не читая реальных док:

- фикстуры `examples/test.docx`, `examples/sample2.html` — синтетика с
  подсаженными данными: их `.md` читать можно (mdcheck на них законно
  не-чист — это и есть приёмочный тест);
- на реальной доке — только `stats "<md>"`: счётчики структуры (строки,
  таблицы, дубли-блоки, CSS-остатки), контент не печатается;
- глазами результат смотрит пользователь — он и так чистит md.

```bash
node "$SKILL/scripts/confluence.mjs" stats "<md>"
```

## Конфиг `scripts/config.json`

`whitelist` (regex — не считать секретом/подозрением, напр. публичные
примерные ключи), `internal_domains` (домены → подозрение HOSTNAME),
`max_suspects`. Менять только по явной просьбе пользователя.

## Ограничения

- Подозрения — эвристика: бывают ложные срабатывания (названия продуктов в
  weak) и пропуски (необычные имена). Список ведёт глаз пользователя, но не
  заменяет его.
- gitleaks + regex не знают всех форматов секретов; кодовые креды в прозе
  ловятся только ключевыми словами (`пароль:`, `password=` …).
- Вложения и картинки не конвертируются (`[image]`-плейсхолдеры).
